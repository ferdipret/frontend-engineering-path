# Capstone Projects

> Stage: 4 · Mastery
> Proof of mastery is shipped work. Each capstone combines many modules; treat them as products, with real users if you can find them.

## Capstones

- [ ] Production SaaS app - auth, billing-shaped flows, dashboard, settings, emails; tested, monitored, deployed with CI/CD
- [ ] Design system - tokens, 20+ accessible components, docs site, visual regression tests, published and versioned
- [ ] Real-time collaborative tool - a whiteboard or document editor with presence, conflict resolution, and offline support
- [ ] Performance showcase - a content or commerce site that scores all-green Core Web Vitals in the field on mid-range mobile
- [ ] Developer tool - a CLI, bundler plugin, lint rule set, or browser extension that others install
- [ ] From-scratch framework - a small UI framework with reactivity, components, and a router, plus a write-up of what you learned

## For every capstone

- [ ] Written design doc - requirements, architecture, and trade-offs before you build
- [ ] Accessibility audit - keyboard and screen reader verified, WCAG 2.2 AA
- [ ] Security review - threat model, strict CSP, dependency audit, and authorisation tests
- [ ] Performance budget - defined up front and enforced in CI
- [ ] Test strategy - unit, component, and end-to-end coverage of critical flows
- [ ] Production operations - error tracking, RUM, and a tested rollback
- [ ] Retrospective - a public write-up of what worked, what didn't, and what you'd change

## Mastery checks

- [ ] Teach it - explain any module in this path to a junior engineer without notes
- [ ] Debug anything - diagnose an unfamiliar production issue from symptoms to root cause
- [ ] Decide well - choose an architecture for a new product and defend it to sceptical peers
- [ ] Mock system design - complete three frontend system design interviews with a peer
- [ ] Leave it better - land an improvement that outlives your involvement in a team or open-source project
