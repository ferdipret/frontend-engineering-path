# Engineering Craft and Leadership

> Stage: 4 · Mastery
> At senior levels, technical skill is assumed. What distinguishes a master is judgement, communication, and making everyone around them better.

## Code craft

- [ ] Readable code — names, small functions, and structure that explain intent
- [ ] Refactoring — improve design in small, safe, behaviour-preserving steps
- [ ] Simplicity — choose the boring solution; delete code when you can
- [ ] Debugging method — form hypotheses, bisect, and isolate rather than guess
- [ ] Reading code — get productive in an unfamiliar codebase quickly
- [ ] Comments and docs — explain why, not what; keep READMEs current

## Collaboration

- [ ] Small pull requests — reviewable changes with clear descriptions
- [ ] Giving code review — kind, specific, and focused on what matters
- [ ] Receiving code review — respond without defensiveness
- [ ] Technical writing — design docs, proposals, and clear async updates
- [ ] Working with design — push back constructively, propose alternatives, prototype
- [ ] Working with product — challenge requirements and negotiate scope
- [ ] Working with backend — agree contracts early and unblock yourself with mocks
- [ ] Pairing — drive and navigate effectively

## Delivery

- [ ] Breaking down work — slice a project into shippable increments
- [ ] Estimation — give ranges, surface risk, update early
- [ ] Prioritisation — weigh impact against effort; say no clearly
- [ ] Shipping iteratively — deliver the thin slice first, then improve
- [ ] Managing ambiguity — turn a vague problem into a concrete plan
- [ ] Ownership — follow work through to production and its outcomes

## AI-assisted engineering

- [ ] Coding assistants — use them effectively for scaffolding, refactors, tests, and exploration
- [ ] Context and prompting — give agents the context, constraints, and checks they need
- [ ] Verifying output — review AI-written code as critically as any other
- [ ] Knowing the limits — recognise when the tool is wrong and when to do it by hand
- [ ] Agent security — sandboxing, permissions, and prompt injection risks when an agent reads untrusted content

## Building AI features

- [ ] Building AI features — choose where a model helps, and design for output that varies from run to run
- [ ] Streaming interfaces — render tokens as they arrive, with cancel, retry, and partial-output states
- [ ] Tool calls and structured output — let a model call your functions and return data your UI can trust
- [ ] AI feature UX — latency, cost, uncertainty, citations, feedback controls, and a fallback when the model fails
- [ ] Evaluating AI features — build an eval set and measure quality before and after every prompt or model change

## Leadership

- [ ] Mentoring — help someone else grow through pairing, feedback, and sponsorship
- [ ] Technical direction — set a vision and bring a team along
- [ ] Driving consensus — lead a cross-team decision to a conclusion
- [ ] Raising the bar — improve standards through tooling, examples, and docs rather than gatekeeping
- [ ] Hiring — interview well and assess fairly
- [ ] Influence without authority — change things you don't own

## Staying current

- [ ] Curated sources — follow a small set of high-signal newsletters, blogs, and release notes
- [ ] Evaluating hype — judge new tools on fundamentals, not excitement
- [ ] Learning in public — write or speak about what you learn
- [ ] Open source — contribute a meaningful change to a project you use
- [ ] Depth and breadth — keep one specialism deep while staying broadly competent
